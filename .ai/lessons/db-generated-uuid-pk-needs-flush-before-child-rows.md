# Flush a DB-generated uuid PK before creating child rows that reference it

**Context**: Every Orva posting route (AP bill/payment post, AR post/receipt
post, period close, payroll post) built a `GlJournal` header with
`tem.create(...)` and immediately created `GlJournalLine` rows with
`journalId: journal.id` in the same unit of work. All six failed at runtime:
`Value for GlJournalLine.journalId is required, 'undefined' found`.

**Problem**: Orva entities declare uuid PKs with
`@PrimaryKey({ defaultRaw: 'gen_random_uuid()' })` — the id is generated by
Postgres, so `entity.id` is `undefined` until a flush hydrates it from
RETURNING. Passing an app-generated `crypto.randomUUID()` as `id` does not
work either: the insert still uses the DB default, so child FKs point at a
uuid that never exists (FK violation). The bug is invisible in unit tests
(pure-math libs) and in `makeCrudRoute` hooks (`afterCreate` runs post-flush).

**Rule**: When a hand-written route creates a parent row with a
`defaultRaw`-generated PK and child rows referencing it in the same
transaction, `await tem.flush()` the parent immediately after
`tem.persist(parent)` and only then create the children from `parent.id`.
Do not pre-assign the uuid app-side.

**Applies to**: All `@orva/*` posting/close routes under
`src/modules/orva_finance/api/**` and `src/modules/orva_hr/api/**`, and any
future route that writes a header + lines pair inside `withTenantRls`.
