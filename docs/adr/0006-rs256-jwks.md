# ADR 0006 — ID token ย้ายจาก HS256 เป็น RS256 + JWKS สาธารณะ

- **สถานะ**: Accepted (2026-08-15) — แทนที่ส่วน HS256 ของ [ADR 0002](0002-oidc-hs256-foundation.md)
- **เกี่ยวข้อง**: `orva_auth::keys`, `/.well-known/jwks.json`

## บริบท

ADR 0002 เลือก HS256 (shared secret) สำหรับ v0.1 เพราะยังไม่มี relying party ภายนอก
ตอนนี้ ORVA กำลังจะต่อบริการภายนอกจริง (OpenWorker ผ่าน Agent API แล้ว และ OSS
module อย่าง Horilla/InvenTree จะตามมาแบบแยก process) — ทุกตัวที่อยาก verify ID token
ด้วย HS256 ต้องถือ secret เดียวกับ ORVA ซึ่งแปลว่า**ปลอมได้ด้วย** (symmetric)
จุดนี้คือเงื่อนไข "ต้องย้ายเป็น RS256" ที่ ADR 0002 ระบุไว้ล่วงหน้า

## การตัดสินใจ

### ลายเซ็น

- ID token เซ็นด้วย **RS256** (RSA 2048 + SHA-256) — asymmetric: ORVA ถือ private key
  ตัวเดียว, ทุกคน verify ได้จาก public key
- JWT header ใส่ `kid` = **JWK thumbprint ตาม RFC 7638** — เตรียมทางให้ key rotation
  ในอนาคต (JWKS ถือหลาย key ได้ relying party เลือกจาก kid)
- HS256 ถูกถอดออกทั้งหมด — ไม่มี dual-mode ให้สับสน (token เก่าหมดอายุภายใน 24 ชม.
  ตาม session TTL อยู่แล้ว การ cut over จึงไม่ต้องมี migration period)

### การเผยแพร่ public key

- `GET /.well-known/jwks.json` — JWKS มาตรฐาน (kty/n/e/alg/use/kid)
- discovery document เพิ่ม `jwks_uri` และเปลี่ยน
  `id_token_signing_alg_values_supported` เป็น `["RS256"]`

### การจัดการ key

- `orva_auth::JwtKeys` โหลดจาก private key PEM (PKCS#8) ที่ path ใน config
  (`auth.rsa_key_path`, env `ORVA_JWT_RSA_KEY_PATH`)
- **dev bootstrap**: ไฟล์ไม่มี → server generate ให้เอง เขียนเก็บที่ path เดิม
  พร้อม log เตือน — ทำให้ `cargo run` แรกใช้งานได้ทันทีโดยไม่ต้องตั้งค่าอะไร
- `config/keys/` อยู่ใน `.gitignore` — private key ห้ามเข้า repo เด็ดขาด
- **production**: ต้อง provision key เองเสมอ (key หาย = token ที่ออกไปแล้วทั้งหมด
  verify ไม่ผ่านทันที) — ยังไม่มี rotation อัตโนมัติใน scope นี้
- RSA keygen เป็น pure Rust (`rsa` crate) ช้ามากใน debug build — workspace
  ตั้ง `opt-level = 2` เฉพาะ `rsa`/`num-bigint-dig` เพื่อให้ test ที่ generate key เร็วพอ

## ผลลัพธ์

- Relying party ภายนอก verify ID token ได้จาก JWKS ล้วน ๆ ไม่ต้องแชร์ secret —
  พิสูจน์ใน `core/tests/auth_flow.rs::id_token_verifies_against_published_jwks`
  (test เล่นบท relying party: ดึง JWKS ผ่าน HTTP แล้ว verify จาก n/e เอง)
- `ORVA_JWT_SECRET` ถูกถอดออกจาก config — ผู้ deploy เดิมต้องเปลี่ยนมาใช้
  `ORVA_JWT_RSA_KEY_PATH` แทน
- สิ่งที่ยังไม่ทำ (ตั้งใจ): key rotation, Authorization Code redirect flow
  (ยังเป็น gap ของ ADR 0002 ที่เหลืออยู่ — รอ relying party ที่ต้องการ SSO จริง)
